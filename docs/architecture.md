Reason: the author's InfluxDB Cloud may be TSM (v2) or Serverless (v3), and InfluxQL is the common denominator; it also covers self-hosted v1/v2/v3. Flux and SQL are out of scope.

## Architecture
- The Flutter app is the settings dashboard only: it manages connections and widget definitions and writes them to shared storage.
- Native widgets read the definitions, query InfluxDB themselves in the background, and render natively. `HomeWidget.renderFlutterWidget` cannot be used for charts because it does not work while the app is fully in the background.
- Query and parse logic exists once per platform (Swift, Kotlin, plus Dart wherever the app itself talks to InfluxDB). The implementations are kept consistent by shared fixtures (see `docs/testing.md`) and one widget-definition format.
- iOS configuration: widgets are configured through AppIntents (`AppIntentConfiguration`, iOS 17+) with an `EntityQuery` that lists the definitions the app stored in the App Group.
- Values and the indicator lamp update on widget refresh only (Android: WorkManager every 15 minutes, system update every 30 minutes, ↻ button). No server and no server push (APNs/FCM); threshold notifications are local notifications posted by the native refresh code (see "Threshold notifications").

## Platform limits that shape the design
- iOS: refreshes are budgeted by the system (roughly 40-70 background reloads per day for a frequently viewed widget). Network requests belong in the timeline provider, never in views.
- Android: `updatePeriodMillis` allows at most one update per 30 minutes; WorkManager allows about every 15 minutes.

## Architectural decisions
- **State management & DI:** `flutter_riverpod` (`mocktail` for unit and widget tests).
- **Schema configuration:** Guided schema selection in the widget editor — automatic discovery via InfluxQL (`SHOW MEASUREMENTS`, `SHOW FIELD KEYS` including `fieldType`, `SHOW TAG KEYS`, `SHOW TAG VALUES`) presented via searchable bottom-sheet pickers, tag-filter chips, multi-field selection, explicit loading/error/reload feedback, and a manual free-text toggle fallback.
- **API token storage:** Tokens are stored in `EncryptedSharedPreferences` (Android) and the App Group Keychain (iOS `group.io.github.mgasc.influx_sensor_widgets`) via `flutter_secure_storage`; connection metadata and widget definitions (`schemaVersion: 1`) are stored as JSON in `home_widget` shared storage.
  - **Android Secure Storage:** `encryptedSharedPreferences: true` (accessed in native Kotlin via AndroidX Security `EncryptedSharedPreferences`).
  - **iOS Secure Storage:** App Group `group.io.github.mgasc.influx_sensor_widgets`, `kSecAttrAccessibleAfterFirstUnlock`.
  - **Token Key Format:** `influx_token_<connectionId>`.
- **Shared Storage Keys (`lib/core/constants/storage_keys.dart`):**
  - App Group: `group.io.github.mgasc.influx_sensor_widgets`
  - Android Prefs: `HomeWidgetPreferences` (primary, backed by `home_widget`) and `sensor_widgets_prefs` (fallback)
  - Widget Definitions Key: `widget_definitions_v1`
  - Connections Key: `connections_metadata_v1`
  - Token Prefix: `influx_token_<connectionId>`
  - Cache Prefix: `widget_cache_<widgetId>`
  - Native only (never read or written by the app): `widget_alert_state_<widgetId>` (rules that matched on the last refresh, JSON list of `{target, operator, value}`, Android prefs and iOS App Group) and, on iOS, `widget_network_failure_since_<widgetId>` (start of the current network failure streak). On Android the failure streak lives inside the cache JSON as `networkFailureSince`.
- **Widget Definitions Contract (`schemaVersion: 1`):**
  - Stored under `fixtures/widget_definitions/widget_definitions_v1.json` with 6 widget types: `single_value`, `history_chart`, `indicator_lamp`, `multi_value`, `aggregate`, `gauge_bar`.
  - Immutable models: `InfluxConnection`, `WidgetDefinition`, `ThresholdRule`, `SensorQueryItem`, `SensorDataPoint`, `FormulaVariable`.
  - Optional formula engine: `formula` (String arithmetic expression with operators `+`, `-`, `*`, `/`, unary minus, parentheses) and `formulaVariables` (mapping `A`, `B`, ... to InfluxDB fields, optional distinct measurements and tag filters).
- **Formula Engine & Cross-Platform Evaluator (Milestone 3):**
  - Evaluates formulas consistently across Dart (`FormulaEvaluator`), Android Kotlin (`FormulaEvaluator.kt`), and iOS Swift (`FormulaEvaluator.swift`).
  - Validated by shared fixtures in `fixtures/formula/evaluator_cases.json`.
  - Floating-point & average rounding: Arithmetic calculations and averages are consistently rounded to avoid IEEE-754 precision artifacts (e.g. `15.150000000000002` -> `15.15`). Decimal places are capped at a maximum of 2 digits across all platforms (`NumberFormatter` in Dart, `ChartMathAndFormatter` in Android, `WidgetViewHelpers` in iOS).
  - Query optimization: Variables sharing the same measurement and tags are fetched via a single InfluxQL query; distinct measurements/tags are fetched via parallel/sequential queries and joined locally.
  - Transparent error propagation: Division by zero, syntax errors, and missing measurement values produce explicit, user-visible error badges/messages rather than silent zero values.
- **Formula contract v2 (Milestone 4; Dart: Task_22, Kotlin and Swift: Task_23):**
  - Grammar (precedence low to high): comparison (`< > <= >= == !=`, result `1.0`/`0.0`, left-associative), `+ -`, `* /`, unary `-`, primary. No unary `+`, no `^` (use `pow`).
  - Functions: `min`/`max` (1..n args), `clamp(x, lo, hi)` (`lo > hi` is a domain error), `abs`, `pow`, `sqrt`, `ln`, `log10`, `exp`, `round` (half away from zero), `floor`, `ceil`, `if(cond, a, b)` (lazy: only the chosen branch is evaluated; non-zero is true). Constants `pi` and `e`; variables and steps with the same name win over constants.
  - `formulaSteps` (`[{name, expression, label?}]`, optional, `schemaVersion` stays 1): evaluated in order, each step sees variables and earlier steps only. `formula` is the final result expression and may use steps. Step names must be identifiers, unique, not equal to a variable name or a function name.
  - Stable error codes (`FormulaException.code`, used as `expected_error` in fixtures): `syntax_error`, `division_by_zero`, `missing_variable`, `unknown_function`, `wrong_arity`, `domain_error` (`sqrt(-1)`, `ln(0)`, `log10(<=0)`, non-finite `pow`/`exp`/arithmetic result), `step_reference_error` (forward/self reference, duplicate or reserved step name).
  - Fixtures: `fixtures/formula/evaluator_cases.json` keeps `valid_cases`/`error_cases` (v1, unchanged) and adds `v2_valid_cases`/`v2_error_cases` with optional `steps`. Dart, Kotlin (`FormulaEvaluatorV2Test`) and Swift (`FormulaEvaluatorV2Tests`) run both sections. Kotlin and Swift expose the same error codes (`FormulaException.code` / `FormulaError.code`), the same API (`evaluate(..., steps)`, `validateSyntax`, `validateSteps`, `extractVariables`) and parse `formulaSteps` (`FormulaStep` in `model/` resp. `WidgetModels.swift`). Widget fixture with steps: `fixtures/widget_definitions/widget_definition_formula_steps.json`. Native refresh paths (`WidgetRefreshWorker`, `SensorTimelineProvider`) pass `formulaSteps` to the evaluator. Swift is only verified once the GitHub Actions run is green.
  - API: `FormulaEvaluator.evaluate(formula, vars, steps:)`, `validateSyntax` (English message, includes 1-based `Position N`), `validateSteps(steps, formula, variableNames:)`, `syntaxError`/`stepsError` (the exception with `FormulaErrorKind`, translated by the UI), `extractVariables` (skips functions and `pi`/`e`). `WidgetDefinition.isValid` validates formula and steps.
- **Formula over time buckets (Task_24, Dart):**
  - `FormulaCalculationService.calculateSeries` queries every variable group with `SELECT MEAN(field) AS field ... GROUP BY time(interval) fill(null)` (`InfluxQlQueryBuilder.buildBucketedMultiFieldQuery`), merges the buckets by timestamp and evaluates `formula` + `formulaSteps` per bucket. `calculateAggregate` applies the formula per bucket first and then takes min/max/mean. Single value, lamp and gauge keep using the latest raw values per variable (`calculateFormula`).
  - Optional field `gapPolicy` (`skip` default | `previous`): `skip` drops buckets with a missing variable; `previous` carries the last known value of each variable forward (buckets before the first value of every variable are still skipped). Gap handling is done in Dart on `fill(null)` results, so it does not depend on `fill(previous)` support of the InfluxDB version.
  - Errors: a variable without any data throws `MissingVariableException`; a failing bucket (e.g. division by zero) is listed in `FormulaSeriesResult.errors` and shown in the preview (`WidgetPreviewData.bucketErrors`); if no bucket succeeds the first error is thrown. No silent 0.
  - `DurationUtils.effectiveBucketInterval` limits a query to 300 buckets (coarser interval) and derives about 60 buckets when no `aggregationInterval` is set.
  - Fixture for native parity: `fixtures/influx/bucketed_multi_field_response.json`.
  - Native parity (Task_25): Kotlin `FormulaSeriesCalculator` + `DurationUtils` + `InfluxQlBuilder.buildBucketedMultiFieldQuery` + `InfluxResponseParser.parseBucketedFields`; Swift `FormulaSeriesCalculator.swift` + `DurationUtils.swift` + the same builder/parser functions. `WidgetRefreshWorker` (Android) and `SensorTimelineProvider` (iOS) use them for history chart and aggregate widgets with a formula. Partial bucket errors are stored as `warning` (Android cache JSON, shown via `WidgetUiState.warningMessage`) resp. `CachedSensorData.warningMessage` (iOS, red overlay); a total failure uses the existing error path. Android Glance and WidgetKit reuse the cached `points`/`aggregates`, so no rendering change was needed beyond the warning line.
- **Multi-value row formulas (Task_26):** `SensorQueryItem` gets optional `formula`, `formulaVariables`, `formulaSteps` (Dart, Kotlin, Swift; fixture `fixtures/widget_definitions/widget_definition_multi_formula.json`). For a formula row `field` is only the row identifier (and cache key). Rows are independent: they inherit measurement, tag filters and decimals from the widget, are calculated from the latest values of their own variables (`calculateItemFormula` / `FormulaSeriesCalculator.calculateItemLatest`) and a failing row is reported in `WidgetPreviewData.multiErrors` (Dart), the cache key `valueErrors` (Android, shown as `Fehler: ...`) resp. `CachedSensorData.multiErrors` (iOS) without hiding the other rows. `WidgetDefinition.isValid` validates every row formula.
- **Formula editor (Task_27):** `FormulaEditorSection` (additive API, old keys unchanged) offers, besides the formula field: insert chips (variables, steps, functions) at the cursor, an optional step list (`onStepsChanged`, rows `step_name_i`/`step_expression_i`) and a variable dialog built from `SearchableSchemaPicker`s (measurement, field, tag key/value with chips, label) fed by injectable loaders (`FieldInfoLoader`, `TagKeyLoader`, `TagValueLoader`, wired to `SchemaDiscoveryController.getFieldInfos/getTagKeys/getTagValues` in `WidgetEditorScreen`). Free text stays possible in every picker. The section is shown for all single-value-like types; Multi-Value widgets get a "Berechnete Zeilen" card (`multi_formula_rows_section`) where each row is a `SensorQueryItem` with its own `FormulaEditorSection(showEnableSwitch: false)`. Plain rows (`MultiFieldSelector`) and formula rows are kept in separate lists and merged on save.
- **Formula help and templates (Task_28):** `lib/presentation/help/formula_help_content.dart` holds all help data as functions of `AppLocalizations` (`formulaHelpEntries(l10n)` per function/constant with a runnable example and expected result, `formulaHelpSections`, `formulaTemplates`) and `formula_help_screen.dart` renders it (`FormulaHelpScreen(applyEnabled)`). `FormulaEvaluator.functionNames` is the source of truth; a test requires a help entry for every function and evaluates every example, so help and evaluator cannot drift. Entry points: help icon in `FormulaEditorSection` (applies a template: formula, steps, placeholder variables with empty `field`, existing assignments with the same name are kept) and `open_formula_help_btn` in the dashboard app bar. Saving a widget is blocked while a variable has no field. Template "IAQ (Sensirion SEN66)": `s_co2/s_voc/s_pm25/s_rh` linear ramps with `clamp`, result `min(...)`.
- **Chart style contract (Task_29, Dart; native in Task_30):** optional `chartStyle` on `WidgetDefinition` (history chart): `colorStops [{value, color "#RRGGBB"}]` (any order, may be empty), `fillArea`, `showGrid`, `showAxes`, `markMinMax` (all default false), `lineWidth` (default 2.0). `toJson` omits defaults. Fixtures: `fixtures/widget_definitions/widget_definition_chart_style.json` and the shared color contract `fixtures/chart/color_interpolation_cases.json` (continuous per-channel linear interpolation between sorted stops, rounded half away from zero, nearest stop outside the range, no stops = no color). Dart: `lib/domain/chart/chart_color.dart` (`parseHexColor`, `formatHexColor`, `interpolateColor`, `buildGradient` = vertical gradient colors/positions for the visible Y range), `HistoryChartPainter` (CustomPainter, no dependency; gradient shader along Y, fill, grid, axis labels, min/max markers) used by `WidgetLivePreviewCard` only when `chartStyle` is set (otherwise the old bar preview is unchanged), and `ChartStyleEditor` (presets green->red / red->green, stop list with hex input, switches, line width) shown for history charts in the editor.
- **Native chart style (Task_30):** Android: `model/ChartStyle.kt`, `glance/chart/ChartColor.kt` (same interpolation contract, fixture-tested), `ChartRenderPlan` (pure geometry: points, gradient, grid, axis labels, min/max, size clamped to 600x240 px = about 576 KB ARGB_8888, so RemoteViews limits are not approached) and `NativeChartBitmapRenderer.renderChart` (LinearGradient shader, fill, grid, labels, markers; returns null for fewer than two points and the widget then uses the old `renderSparkline`). `WidgetUiState` carries `chartValues` and `chartStyle`; widgets without `chartStyle` render exactly as before. iOS: `Models/ChartStyle.swift` (models + `ChartColor`), `StyledHistoryChart` in `SensorWidgetViews.swift` (Swift Charts with `LinearGradient` over the data range as foreground style, `chartYScale(domain:)` = data range so colors align with values, area/grid/axis/min-max options); without `chartStyle` the previous chart is used. Invalid stops are ignored (no usable stops = plain accent line).
- **App UI (Task_31):** `lib/core/theme/app_theme.dart` (`AppTheme.light()/dark()`, Material 3, seed `0xFF00796B`, rounded cards/inputs/buttons, 48 dp minimum button size); `SensorWidgetsApp` uses both themes with `ThemeMode.system` and accepts an optional `home` for tests. Dashboard: redesigned `_WidgetCardItem` (type icon in a rounded container, title, measurement/interval line, type chip, live mini preview `dashboard_card_preview_<id>` (real data via `dashboardPreviewProvider`, the same `fetchPreviewData` query as the editor preview, shown as `dashboard_card_live_<id>`: latest value plus line for history charts, values for the other types; the per-type decorative placeholder while loading or on errors; the app-bar sync button reloads it), popup menu); list has bottom padding for the FAB. Editor: `WidgetTypeSelector` (tiles `type_tile_<wire>` with icon, name and description, `Semantics` button/selected) plus shared `WidgetTypeVisuals` (icons/descriptions). The old `widget_type_dropdown` was removed after the user approved adapting the three existing tests that used it (they now tap the `type_tile_<wire>` tiles; assertions unchanged).

  - **Platform limits:** Android `cornerRadius` only works on Android 12+ (older versions ignore it). iOS draws the widget container shape itself, so `cornerRadius` is parsed but not applied there; `fontScale` scales fixed point sizes and maps to a Dynamic Type step (small / large / xLarge / xxLarge) for text styles. Muted text on Android is the text color at alpha 0xB3 when a custom text color is set. Mutable look of status colors (error red, lamp on/off) is not customizable.
- **Editor accordion:** `WidgetEditorScreen` groups its form into collapsible cards (`EditorAccordionSection`, `lib/presentation/widgets/editor/editor_accordion_section.dart`): `basics` (title, connection, type tiles), `data_source` (measurement, field/rows, tags, formula, unit, decimals), `code` (`WidgetCodeSection`), `type_settings` (only for history chart, indicator lamp, gauge bar, aggregate: the type block, the gap policy and the chart style), `appearance`, `alerts`. Headers are `editor_section_<id>` (semantics `expanded`). Only one section is open at a time (`_openSection`, starts with `basics`); tapping the open header closes it. Closed sections stay mounted but offstage, so their fields keep state and `Form.validate()` still checks them; a failed save opens `basics` (title missing) or `data_source`. Only opening/closing animates (no clipping while open, so floating labels stay visible). The editors shown inside (`WidgetCodeSection`, `AppearanceEditor`, `AlertRulesEditor`, `ChartStyleEditor`) take `embedded: true`: no own card, and no title where the header already shows it (the chart style keeps its title inside `type_settings`).
- **Gap policy in the editor (Task_33):** history charts and aggregates with a formula show a "Lücken im Verlauf" card (`gap_policy_skip`, `gap_policy_previous`); `skip` is the default and is not written to the definition, `previous` is stored as `gapPolicy`. Task_33 also fixed a "setState() called during build" in `FormulaEditorSection` when a template changed formula/steps from outside: controllers that already have listeners are now updated after the frame.
- **Threshold notifications (`alerts`):** optional list on every widget type, `[{"target", "operator": "greaterThan"|"lessThan", "value"}]`; `target` is `value` for the primary value (with a formula the calculated value, e.g. IAQ; history chart: latest point), a row `field` of a multi-value widget, or `min`/`max`/`mean` of an aggregate. Fixtures: `fixtures/widget_definitions/widget_definition_alerts.json` (format) and `fixtures/alerts/evaluation_cases.json` (behavior, read by Kotlin and Swift). Rules are edge-triggered: a notification when a rule starts matching, then none until the value went back across the threshold (a changed threshold is a new rule; error caches and missing values keep the previous state). Dart: `AlertRule`, `AlertRulesEditor` card "Benachrichtigungen" in the editor (targets per type from `_alertTargets`), adding a rule calls `NotificationPermission.request()` (`lib/data/platform/notification_permission.dart`, platform channel `sensor_widgets/notifications`, method `requestPermission` → bool; no plugin dependency). Android: `alerts/AlertEvaluator` + `AlertMessage` (pure, tested), `WidgetRefreshWorker.checkAlerts` after each successful cache write, `AlertNotifier` posts on channel `threshold_alerts` (skips silently without `POST_NOTIFICATIONS`), `MainActivity` answers the permission channel (Android 13+ runtime prompt). iOS: `Alerts/AlertEvaluator.swift` (rule, evaluator, message), `AlertNotifier` (`UNUserNotificationCenter` from the widget extension), called from `SensorTimelineProvider` after a successful fetch; `AppDelegate` answers the permission channel. iOS notifications only fire when WidgetKit reloads the timeline (system budget), so they can be late or skipped; verified only by CI unit tests, not on a device.
- **Plain HTTP InfluxDB servers (Android):** the manifest sets `android:usesCleartextTraffic="true"`. The editor preview uses Dart's `HttpClient`, which ignores Android's network security policy, while the native refresh (OkHttp) obeys it; without the flag an `http://` server (typical for Home Assistant) works in the preview but the home-screen widget never updates (the blocked request counts as a network error and the grace period below keeps old values). Checked by `ManifestNetworkTest.kt`. iOS (App Transport Security) is not covered yet.
- **Network error grace period:** a network failure (Android `InfluxNetworkException`, iOS `InfluxError.networkError`/`URLError`) keeps the last good values on screen for `NetworkErrorGrace` 1 hour of consecutive failures; only then is the error shown. Other errors (auth, query, formula) show at once, and without earlier data the error shows at once too. Android: `worker/NetworkErrorGrace` (pure, tested) writes the kept cache with `networkFailureSince`; a network failure makes the worker return `Result.retry()` (WorkManager backoff), and all refresh work requires `NetworkType.CONNECTED` (`WidgetRefreshWorker.refreshConstraints`), so a refresh right after a Doze wake-up waits for the connection. iOS: `NetworkErrorGrace.fallback` in `SensorTimelineProvider`.
- **Android widget refresh and sizing:** `WidgetRefreshWorker` runs through `WidgetRefreshRunner` (pure, tested) and always calls `SensorGlanceAppWidget.refreshAll` afterwards (also after a failed refresh), which bumps the Glance state key `refresh_version` and updates every placed widget. `provideContent` reads that key and reloads definition plus cache from storage via `remember(refreshVersion)`, so a running Glance session never keeps the data of its first render. `SensorGlanceWidgetReceiver` schedules the 15-minute periodic work in `onEnabled` and `onUpdate` (KEEP policy, so widgets placed before this existed get it), enqueues a one-time refresh in `onUpdate` (system 30-minute period, app saved definitions, widget placed) and cancels the periodic work in `onDisabled`. The ↻ button only enqueues the one-time work; the worker re-renders. Its glyph stays small, but the tap target is a `WidgetSizing.REFRESH_TOUCH_TARGET_DP` (56 dp) box in the top-end corner drawn above the content (`RefreshTapTarget`), so it wins over the root "open app" click; the header keeps `REFRESH_GLYPH_SLOT_DP` free for it. The button also shows on the error view. Sizing: `sizeMode = SizeMode.Exact`; `WidgetSizing` (pure, tested) derives the chart area from `LocalSize` (chart image uses `defaultWeight()` + `ContentScale.FillBounds`, bitmap rendered at that aspect ratio within a 180k-pixel budget, `ChartRenderPlan` caps 800x600), the number of multi-value rows that fit, and a 1..2x scale for the primary value of single-value and indicator widgets. The widget picker (`SensorWidgetConfigActivity`) uses `WidgetConfigTheme` (no action bar), draws edge-to-edge on every Android version and pads its root by system bar and cutout insets (`ConfigScreenInsets`, pure, tested), because Android 15 otherwise draws the list below the status bar.
- **iOS widget extension target:** Implemented in `ios/SensorWidgetsExtension/` using Swift 5.9+, SwiftUI, Swift Charts (`Charts`), and AppIntents (`SelectWidgetIntent`, `SensorTimelineProvider`, `SensorWidgetViews`). - **Localization (app and native widgets):** supported languages English and German; the device language decides, every other language falls back to English.
  - Flutter: `flutter gen-l10n` (`l10n.yaml`, `generate: true`) turns `lib/l10n/app_en.arb` (template, English) and `lib/l10n/app_de.arb` into `lib/l10n/generated/` (committed, regenerated by `flutter pub get`/`flutter gen-l10n`). `preferred-supported-locales: [en]` keeps English first in `AppLocalizations.supportedLocales`, which makes it the fallback of `MaterialApp`'s locale resolution (gen-l10n sorts alphabetically otherwise). Widgets use `AppLocalizations.of(context)`; Riverpod controllers without a context read `appLocalizationsProvider` (`lib/presentation/providers/l10n_provider.dart`, same resolution, rebuilt on `didChangeLocales`).
  - Domain errors carry no language: `FormulaException` has a `FormulaErrorKind` plus `args` and an English `message` for logs; `lib/l10n/formula_error_text.dart` (`formulaErrorText`, `errorText`) translates them. `FormulaEvaluator.syntaxError`/`stepsError` return the exception (the UI uses these); `validateSyntax`/`validateSteps` still return English strings. `InfluxErrorFormatter.format`, `WidgetCodeCodec.decode` and the help content (`formulaHelpSections`/`formulaHelpEntries`/`formulaTemplates`) take an `AppLocalizations`.
  - The two LLM prompts are long texts with JSON braces that clash with ICU placeholders, so they live in `lib/presentation/help/formula_llm_prompt_texts.dart` (`PromptTexts`, one set per language, English fallback) instead of the ARB files.
  - Kept as is in every language: widget type names (`WidgetType.label`, e.g. "Single Value"), formula function names, decorative `MIN/Ø/MAX`.
  - Android: `res/values/strings.xml` (English, fallback) and `res/values-de/strings.xml`. Glance views, the widget picker and the notification channel use `getString`; worker, alert texts, cache mapper and bucket summaries get a `WidgetTexts` (`l10n/WidgetTexts.kt`, `WidgetTexts.of(context)` in production) so they stay JVM-testable. Kotlin `FormulaException` mirrors the Dart kinds (`FormulaErrorKind`, English `message`); `WidgetTexts.formulaError` translates. Error texts are written into the widget cache in the device language at refresh time, so a language change shows after the next refresh.
  - iOS: the widget extension is a Swift package without resources, so `Localization/WidgetTexts.swift` holds one table per language (`english`, `german`) and `WidgetTexts.current` (from `Locale.preferredLanguages`, English fallback) is used by `FormulaError`, `AlertMessage`, `FormulaSeriesCalculator` and the views. App Intent titles and the widget description stay English (they need compile-time `LocalizedStringResource` catalogs). Verified only by CI.
  - Adding a language: `lib/l10n/app_<lang>.arb`, a `PromptTexts` set, `res/values-<lang>/strings.xml`, a Swift table plus its `byLanguage` entry.

- **Formula LLM prompt:** `buildFormulaLlmPrompt(l10n: ...)` (`lib/presentation/help/formula_llm_prompt.dart`, pure) builds a prompt in the app language (texts in `formula_llm_prompt_texts.dart`, see "Localization") from `formulaHelpEntries` (so it follows the evaluator), the selected measurement(s) and schema fields with types. It tells the LLM to answer "OK" first and then return only the formula (plus optional steps) and the variable-to-field mapping. `FormulaEditorSection` offers a copy button (`copy_llm_prompt_button`, clipboard) and a share button (`share_llm_prompt_button`, `share_plus`; injectable via `onSharePrompt` for tests). The share sheet itself is not covered by automated tests.

- **Widget as code:** the editor always shows `WidgetCodeSection` (for every widget type, with or without a calculation formula) (`lib/presentation/widgets/editor/widget_code_section.dart`): a large monospace text area (`widget_code_field`) holding the whole widget as JSON. `WidgetCodeCodec` (`lib/domain/widget_code/widget_code_codec.dart`, pure) encodes a `WidgetDefinition` without `id`/`connectionId` and decodes pasted code (optionally in a markdown fence) on top of the current editor widget: `id` and `connectionId` always come from the editor, `title` and `measurement` fall back to it. Decoding validates type, formulas (syntax, undefined variables, variables without field, also for multi-value rows), `gapPolicy`, `chartStyle`, `appearance` and completeness, and returns readable errors instead of throwing. "Code übernehmen" (`widget_code_apply_button`) moves the result into the editor state (`_applyWidgetCode`); the area follows the form until the user edits it ("Aus Formular neu erzeugen" resets). The JSON format is the widget-definition format, so it must stay in sync with `WidgetDefinition` (no separate format). One toolbar row with short labels holds three buttons: "KI-Prompt" (`copy_widget_prompt_button`) copies `buildWidgetCodePrompt`, "Kopieren" (`copy_widget_code_button`) copies the current text of the code area, "Einfügen" (`paste_widget_code_button`) replaces the code area with the clipboard text and applies it right away (errors keep the pasted text, marked as not applied; an empty clipboard changes nothing). There is no share button any more. `buildWidgetCodePrompt` which describes the formula language, all widget types and JSON keys with an example (a test decodes that example with the codec), the selected schema, and the current code. The formula-only prompt (`buildFormulaLlmPrompt`) remains on multi-value formula rows; the main formula section hides its prompt buttons (`showPromptButtons: false`) because the code card replaces them.
